# US-047: El repositorio no contradice al sistema desplegado

> **Navegación del Framework SDD:**
> [EXT-002](../../../04_governance_and_quality/external_reviews/EXT-002-revision-de-entrega-final.md) | [Índice de historias](../indice_user_stories.md) | [Índice de tickets](../../12_tickets/indice_tickets.md)

---

## Narrativa (Comportamiento y Negocio)
**Como** persona que llega al proyecto —a revisarlo, a desplegarlo o a retomarlo dentro de seis meses,
**Cuando** leo lo que el repositorio dice de sí mismo,
**Quiero** que coincida con lo que el sistema hace de verdad,
**Para** no perder tiempo persiguiendo una ruta que no existe ni descartando a mano un archivo que sobra.

---

## Precondiciones
- `openapi.yaml` es la fuente de verdad del contrato; el README lo resume, nunca al revés.
- Ninguna de estas correcciones cambia el comportamiento del sistema: sólo lo que el repositorio afirma sobre él.

---

## Criterios de Aceptación (BDD Gherkin)

@critical @smoke
### Escenario 1: Los ejemplos de la documentación funcionan
*   **Given** los ejemplos de llamada documentados en la sección de API del README
*   **When** se comparan uno a uno con el contrato publicado
*   **Then** la ruta, el método y los campos obligatorios coinciden, sin ninguno omitido

@critical
### Escenario 2: El contrato no arrastra avisos estructurales
*   **Given** el documento del contrato
*   **When** se valida con el linter declarado en `AGENTS.md`
*   **Then** no queda ningún aviso por operaciones con etiquetas sin declarar

@edge
### Escenario 3: No hay artefactos huérfanos que confundan
*   **Given** alguien que busca el esquema de base de datos del proyecto
*   **When** recorre el repositorio
*   **Then** encuentra exactamente uno, el que el arranque usa de verdad

---

## Criterios de Aceptación No Funcionales (NFRs)
*   **Cero cambios de comportamiento:** ningún test existente cambia de resultado, y el contrato no introduce cambios rompedores (verificable con la guardia de deriva del proyecto).
*   **Reproducibilidad:** el gestor de paquetes queda declarado, de modo que una instalación local resuelva el mismo árbol que la integración continua.

## Decisiones de negocio consultadas con el humano (Fase 1.5 del workflow 01, 2026-09-25)
- **Esquema duplicado:** se borra, no se documenta. Nada lo referencia, tiene un único archivo y declara un generador que el proyecto ya no usa; conservarlo con una nota mantiene la confusión y añade algo más que mantener.
- **Etiquetas globales del contrato:** entran en esta historia. Las 44 operaciones arrastran el mismo aviso porque el documento nunca las declara; es un bloque de una vez y encaja con una historia que va de alinear lo publicado.
- **Reducir el README (R-04 del informe):** **queda fuera**. Reestructurar 92 KB no es limpieza, es decidir qué cuenta el proyecto de sí mismo y a quién; mezclarlo con cinco correcciones de una línea haría que esta historia no se pudiera cerrar.
- **Origen:** recomendaciones R-01, R-05, R-08, R-11 y R-12 de [`EXT-002`](../../../04_governance_and_quality/external_reviews/EXT-002-revision-de-entrega-final.md).
