# US-040: Impedir el consumo de un remanente vencido

> **Navegación del Framework SDD:**
> [Revisión externa EXT-001](../../../04_governance_and_quality/external_reviews/EXT-001-auditoria-ux-ui.md) | [Índice de historias](../indice_user_stories.md) | [Índice de tickets](../../12_tickets/indice_tickets.md)

---

## Narrativa (Comportamiento y Negocio)
**Como** Responsable de inocuidad del restaurante,  
**Cuando** un remanente supera su fecha de vencimiento,  
**Quiero** que el sistema impida consumirlo y solo permita descartarlo,  
**Para** que ningún insumo vencido llegue a un plato.

---

## Precondiciones
- Existe un remanente con `expirationDate` anterior al momento actual.
- La persona tiene el permiso `kitchen:remanente_consume`.

---

## Criterios de Aceptación (BDD Gherkin)

@critical @smoke
### Escenario 1: El consumo de un vencido se rechaza
*   **Given** un remanente cuya fecha de vencimiento ya pasó
*   **When** el operario intenta consumirlo
*   **Then** el sistema responde con error de status `422`
*   **And** la respuesta cumple el formato RFC 7807 con code "REMANENTE_EXPIRED" y el remanente no cambia de estado

@critical
### Escenario 2: El descarte del vencido sí procede
*   **Given** el mismo remanente vencido
*   **When** el operario lo descarta con el motivo de vencimiento
*   **Then** el sistema responde `200 OK` y el remanente queda descartado

@edge
### Escenario 3 / Scenario Outline: Separación visual por urgencia
*   **Given** un remanente en el estado <Estado>
*   **When** el operario abre la vista de remanentes
*   **Then** el resultado debe ser <ResultadoEsperado>

  **Examples:**
    | Estado | ResultadoEsperado |
    | "vencido" | "aparece en el grupo Vencidos, con descartar como única acción" |
    | "caduca hoy" | "aparece en el grupo Caduca hoy, con consumir y descartar disponibles" |

---

## Criterios de Aceptación No Funcionales (NFRs)
*   **Rendimiento:** la respuesta de la API y el repintado quedan por debajo de 300 ms con el catálogo actual.
*   **Accesibilidad:** todo elemento interactivo nuevo mantiene el objetivo táctil de 48 × 48 px de `DESIGN.md`, y los estados no dependen solo del color.

---

## Decisiones de negocio consultadas con el humano (Fase 1.5 del workflow 01, 2026-09-18)
- Un remanente vencido solo se puede descartar; consumir queda bloqueado en el backend (decisión del humano, Fase 1.5).
- Es una regla de inocuidad (INV-5), no una preferencia de interfaz: el bloqueo vive en el caso de uso, no en la pantalla.
- `Vencido` y `Caduca hoy` dejan de compartir el nivel de urgencia `critical`.
- Origen: recomendación de la revisión externa [`EXT-001`](../../../04_governance_and_quality/external_reviews/EXT-001-auditoria-ux-ui.md).
