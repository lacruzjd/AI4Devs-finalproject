# US-038: Consultar el historial de movimientos durante el turno

> **Navegación del Framework SDD:**
> [Revisión externa EXT-001](../../../04_governance_and_quality/external_reviews/EXT-001-auditoria-ux-ui.md) | [Índice de historias](../indice_user_stories.md) | [Índice de tickets](../../12_tickets/indice_tickets.md)

---

## Narrativa (Comportamiento y Negocio)
**Como** Operario de cocina con acceso al inventario,  
**Cuando** detecto un descuadre entre lo que dice el sistema y lo que hay en la estantería,  
**Quiero** consultar el historial de movimientos de stock desde el propio turno,  
**Para** resolver la diferencia sin esperar a que un administrador esté disponible.

---

## Precondiciones
- La persona está autenticada y tiene el permiso `stock:read`.
- Existen movimientos registrados (extracciones, consumos, descartes o reposiciones).

---

## Criterios de Aceptación (BDD Gherkin)

@critical @smoke
### Escenario 1: El operario consulta los movimientos del turno
*   **Given** un operario autenticado con `stock:read` y movimientos registrados hoy
*   **When** abre la sección Movimientos desde la navegación principal
*   **Then** el sistema responde `200 OK` con el historial ordenado del más reciente al más antiguo
*   **And** cada movimiento muestra insumo, tipo, cantidad, responsable y fecha

@critical
### Escenario 2: Sin permiso de lectura de stock
*   **Given** una persona autenticada sin el permiso `stock:read`
*   **When** solicita el historial de movimientos
*   **Then** el sistema responde con error de status `403`
*   **And** la respuesta cumple el formato RFC 7807 con code "FORBIDDEN"

@edge
### Escenario 3 / Scenario Outline: Filtro por insumo
*   **Given** que se consulta el historial con el filtro <Filtro>
*   **When** se procesa la petición
*   **Then** el resultado debe ser <ResultadoEsperado>

  **Examples:**
    | Filtro | ResultadoEsperado |
    | "insumoId de un insumo con movimientos" | "200 OK solo con los movimientos de ese insumo" |
    | "insumoId inexistente" | "200 OK con una lista vacía y su estado vacío en pantalla" |

---

## Criterios de Aceptación No Funcionales (NFRs)
*   **Rendimiento:** la respuesta de la API y el repintado quedan por debajo de 300 ms con el catálogo actual.
*   **Accesibilidad:** todo elemento interactivo nuevo mantiene el objetivo táctil de 48 × 48 px de `DESIGN.md`, y los estados no dependen solo del color.

---

## Decisiones de negocio consultadas con el humano (Fase 1.5 del workflow 01, 2026-09-18)
- Quién lo ve: cualquiera con `stock:read`, no solo administración (ADR-007). Supersede el criterio de `TK-050`.
- La pantalla deja `/ajustes` y pasa a ser una sección de primer nivel.
- No se añaden permisos nuevos ni se migran roles existentes.
- Origen: recomendación de la revisión externa [`EXT-001`](../../../04_governance_and_quality/external_reviews/EXT-001-auditoria-ux-ui.md).
