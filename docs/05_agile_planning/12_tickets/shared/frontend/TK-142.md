# 🎟️ TK-142: Parametrizar el upstream de nginx y declarar la infra de Render (`render.yaml`)

> [📖 Índice](../../indice_tickets.md) | [⬅️ ADR-006](../../../../02_architecture_design/adr/ADR-006-render-deployment-topology.md)

## 📝 Descripción

Ejecuta la topología decidida en [`ADR-006`](../../../../02_architecture_design/adr/ADR-006-render-deployment-topology.md): frontend (imagen con nginx) como servicio público, backend como servicio privado, Postgres gestionado — **preservando el mismo origen**, que es la premisa de la que dependen `ADR-005` y la CSP de `TK-141`.

Bloqueante concreto: `apps/frontend/nginx.conf` fija `proxy_pass http://backend:3000` y `listen 8080`. Ambos son alias/puertos de `docker-compose` que no existen en Render.

## 🔀 Alcance

**1. `apps/frontend/nginx.conf` → plantilla parametrizada**

- Renombrar a `default.conf.template` y sustituir el upstream por `${BACKEND_ORIGIN}` y el puerto por `${NGINX_PORT}`.
- **No hace falta entrypoint propio:** la imagen oficial de nginx ya ejecuta `/docker-entrypoint.d/20-envsubst-on-templates.sh` (confirmado en los logs del contenedor durante la verificación de `TK-141`).
- Usar `NGINX_ENVSUBST_FILTER` acotado a esas dos variables — sin filtro, `envsubst` podría tocar variables propias de nginx (`$uri`, `$host`, `$remote_addr`) y la variable `$spa_csp` que introdujo `TK-141`.
- `docker-compose.yml` e `infrastructure/opentofu/main.tf` pasan `BACKEND_ORIGIN=http://backend:3000` y `NGINX_PORT=8080` → **el comportamiento local no cambia**.

**2. `render.yaml` en la raíz** (carve-out del Guard 22 documentado en `ADR-006` §3)

- `restostock-db`: PostgreSQL gestionado.
- `restostock-backend`: private service, `apps/backend/Dockerfile`, health check en **`/health`** (está en la raíz, **no** bajo `/api/v1`).
- `restostock-frontend`: web service público, `apps/frontend/Dockerfile`, con `BACKEND_ORIGIN` apuntando al backend interno.

**3. Variables de entorno** (sin ellas el arranque aborta por Guard 14):

| Variable | Nota |
| :--- | :--- |
| `NODE_ENV=production` | |
| `DATABASE_URL` | de la base gestionada |
| `JWT_SECRET` | ≥16 caracteres |
| `ENCRYPTION_KEY` | ≥16, **obligatoria en producción** (`AUDIT-SEC-004`/`TK-133`) |
| `CORS_ALLOWED_ORIGINS`, `CLIENT_ORIGIN` | URL pública del frontend |
| **`SEED_ADMIN_PIN`** | 🔴 **sin ella NO se crea ningún administrador y nadie puede entrar** — ver notas |

**4. `docs/00_stack_manifest.md` §6:** Render declarado como Cloud Hosting del entorno de revisión (Guard 24, aprobado por el humano el 2026-09-09).
