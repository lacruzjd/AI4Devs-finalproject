# TK-166: Alinear la Documentación de API con el Contrato Publicado

> **Navegación del Framework SDD:**
> [Historia US-047](../../../11_user_stories/shared/US-047.md) | [Índice de tickets](../../indice_tickets.md) | [Matriz de trazabilidad](../../../13_matriz_trazabilidad.md)

---

## Descripción
La sección de API del README documenta una ruta que devuelve 404 y ejemplos a los que les faltan campos obligatorios. Se corrige contra `openapi.yaml`, que es la fuente. De paso se declaran las etiquetas globales del contrato: las 44 operaciones arrastran el mismo aviso del linter porque el documento nunca las declara.

*   **ID US Relacionada:** `US-047`
*   **Módulo / Vertical Slice:** `shared`
*   **Estimación (Story Points):** 3 SP
*   **Prioridad MoSCoW:** Should Have
*   **Prerrequisitos:** ninguno

---

## Alcance de Modificación (Hexagonal Layers)
**Documentación:** sección de API de `readme.md` y `docs/03_persistence_and_api/openapi.yaml`. **Sin cambios de código:** las rutas reales no se tocan; se corrige lo que se dice de ellas.

---

## Mitigación de Riesgos Técnicos
1. **Corregir el README contra la memoria en vez de contra el contrato:** cada ejemplo se verifica contra `openapi.yaml`, y los campos obligatorios contra el esquema de la petición, no contra lo que parezca razonable.
2. **Tocar el comportamiento sin querer:** las etiquetas globales son metadatos del documento; la guardia de deriva del proyecto debe seguir reportando cero cambios rompedores.
3. **Volver a divergir mañana:** el README no debe duplicar el contrato. Donde el detalle viva en `openapi.yaml`, el README enlaza en lugar de copiar.

## Verificación y hallazgos (2026-09-25)

**Auditadas las diez rutas documentadas en §4 una a una contra el contrato.** Nueve eran correctas. Los defectos encontrados fueron cuatro, uno más de los tres que listó el informe externo:

| Dónde | Defecto |
|:---|:---|
| §4.2 extracción | Omitía `fromStorageLocationId`, obligatorio, **y usaba `toLocation`, un campo que no existe** en el contrato: el real es `toStorageLocationId`. El ejemplo habría fallado dos veces |
| §4.8 alta de insumo | Omitía `storageLocationId`, obligatorio desde `US-025` |
| §4.9 alta de receta | Apuntaba a `/api/v1/catalog/recipes`, que devuelve 404 |
| §4.10 reabastecimiento | Omitía `storageLocationId`, obligatorio — **no estaba en el informe** |

**Etiquetas globales:** declaradas las siete que usaban las operaciones sin que el documento las definiera. Avisos del linter: **76 → 32**, y los 32 restantes son de otras dos clases (descripción de operación y contacto), preexistentes y fuera de este ticket.

- Guardia de deriva con `oasdiff`: **sin breaking changes**.
- Linter de contrato: **0 errores**.
- Suite completa, lint y build: en verde.

**Contra la reincidencia:** la cabecera de §4 declara ahora explícitamente que la fuente de verdad es `openapi.yaml` y que esta sección se resume de él. La deriva ocurrió porque el README duplicaba el contrato sin decir cuál manda.

**Residual declarado:** tres menciones a `/api/v1/catalog/recipes` sobreviven en la **prosa histórica** del README (registro de tickets pasados). No se tocan: corregirlas cambiaría el registro de lo que se dijo entonces, y no puedo verificar si aquella ruta se especificó así en su momento. La sección de referencia, que es de donde se copia, está corregida.
