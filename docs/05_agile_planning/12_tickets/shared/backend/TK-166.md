# TK-166: Alinear la Documentación de API con el Contrato Publicado

> **Navegación del Framework SDD:**
> [Historia US-047](../../../11_user_stories/shared/US-047.md) | [Índice de tickets](../../indice_tickets.md) | [Matriz de trazabilidad](../../../13_matriz_trazabilidad.md)

---

## Descripción
La sección de API del README documenta una ruta que devuelve 404 y ejemplos a los que les faltan campos obligatorios. Se corrige contra `openapi.yaml`, que es la fuente. De paso se declaran las etiquetas globales del contrato: las 44 operaciones arrastran el mismo aviso del linter porque el documento nunca las declara.

*   **ID US Relacionada:** `US-047`
*   **Módulo / Vertical Slice:** `shared`
*   **Estimación (Story Points):** 3 SP
*   **Prioridad MoSCoW:** Should Have
*   **Prerrequisitos:** ninguno

---

## Alcance de Modificación (Hexagonal Layers)
**Documentación:** sección de API de `readme.md` y `docs/03_persistence_and_api/openapi.yaml`. **Sin cambios de código:** las rutas reales no se tocan; se corrige lo que se dice de ellas.

---

## Mitigación de Riesgos Técnicos
1. **Corregir el README contra la memoria en vez de contra el contrato:** cada ejemplo se verifica contra `openapi.yaml`, y los campos obligatorios contra el esquema de la petición, no contra lo que parezca razonable.
2. **Tocar el comportamiento sin querer:** las etiquetas globales son metadatos del documento; la guardia de deriva del proyecto debe seguir reportando cero cambios rompedores.
3. **Volver a divergir mañana:** el README no debe duplicar el contrato. Donde el detalle viva en `openapi.yaml`, el README enlaza en lugar de copiar.

---

## Criterios de Aceptación & DoD (Definition of Done)
### Escenario 1 (Happy Path)
*   **Given** los ejemplos de la sección de API del README
*   **When** se comparan con el contrato
*   **Then** ruta, método y campos obligatorios coinciden en todos

### Escenario 2 (Etiquetas)
*   **Given** el contrato con sus etiquetas globales declaradas
*   **When** se valida con el linter declarado en `AGENTS.md`
*   **Then** no queda ningún aviso de etiqueta sin declarar

### Escenario 3 (Sin cambios rompedores)
*   **Given** el contrato modificado
*   **When** se ejecuta la guardia de deriva del proyecto
*   **Then** reporta cero cambios rompedores

### DoD Estricto:
1. **TDD Compliance:** no aplica en el sentido habitual — no hay código nuevo; la verificación es el linter, la guardia de deriva y la comparación contra el contrato.
2. **Precisión Aritmética:** no aplica.
3. **Verificación Total:** cero errores en los comandos de test, build, lint y validación de contrato declarados en `AGENTS.md`.

---

## Instrucciones de Ejecución Autónoma para Agente IA
1. **Leer `openapi.yaml` antes que el README:** el contrato manda; el README se corrige hacia él.
2. **Validar el contrato** y ejecutar la guardia de deriva declaradas en `AGENTS.md`.
