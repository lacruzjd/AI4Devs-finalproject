# TK-165: Documentar el Endpoint de Cambio de PIN en el Contrato

> **Navegación del Framework SDD:**

## Descripción
`POST /api/v1/auth/change-pin` existe en el código —caso de uso, ruta y consumo desde la interfaz— y **no aparece en `openapi.yaml`**. Es el endpoint con el que se rota el PIN, así que la capacidad que `US-046` obliga a usar no está en el contrato que el proyecto publica como fuente de verdad.

Detectado al mapear el impacto de `US-046`; el informe externo no lo señaló.

*   **Módulo / Vertical Slice:** `auth`
*   **Estimación (Story Points):** 1 SP
*   **Prioridad MoSCoW:** Should Have
*   **Prerrequisitos:** ninguno

## Alcance de Modificación (Hexagonal Layers)
**Documentación de contrato:** `docs/03_persistence_and_api/openapi.yaml`. **Sin cambios de código**: el endpoint ya existe y su comportamiento no se toca. Es documentar lo que hay, no cambiarlo.

## Mitigación de Riesgos Técnicos
1. **Documentar lo que se cree en vez de lo que hay:** el esquema de petición y respuesta se escribe leyendo el caso de uso y su validación reales, no de memoria.
2. **Versión del contrato:** añadir un endpoint que ya existía es aditivo para quien consume; se sube la versión menor y se justifica en la nota del propio archivo, como el resto.

## Verificación (2026-09-25)

Documentado leyendo el validador real, no de memoria: `userId` no vacío, `currentPin` y `newPin` con el patrón de 4 a 6 dígitos, y respuesta `{ success, message }`. Los códigos de error salen de los constructores de las excepciones del dominio: 401 para PIN actual incorrecto, 403 para cuenta bloqueada y 404 para usuario inexistente.

- Linter de OpenAPI: **0 errores**.
- `check_contract_drift.sh` con `oasdiff`: **sin breaking changes** entre `HEAD` y el árbol de trabajo. Es aditivo por construcción — publica un endpoint que ya existía.

**Anotado, no corregido:** el endpoint hereda el único aviso que el contrato ya arrastra en sus 44 operaciones (`operation-tag-defined`: el documento nunca declara `tags` globales). Añadir ese bloque los cerraría los 44 de una vez, pero es limpieza de contrato y corresponde a R-01 de `EXT-002`, no a este ticket.
